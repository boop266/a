# 果てなき道 — 作るときの芯（ユーザーの言葉の「奥」）

- 注文は「その一点を足せ」ではなく「その注文が示す方向へ、世界全体を引き上げろ」。遊園地と言われたら、遊園地を足すのではなく、世界のどこへ行っても同じ密度・同じ驚きがある状態にする。
- 一番ワクワクしたのは、指示ゼロで自分で世界を構想した最初のウィザードリィ。言われたことの実装係になった瞬間に質が落ちる。毎回「自分が遊びたい世界か」で判断し、言われていないことこそ考える。
- 量（場所の数・機能の数）で応えない。体験の質で応える。チェックリストを全部満たしたのに退屈、が最悪の失敗。
- ともだちは喋る置物ではない。セリフを増やすほど安っぽくなる。存在感は行動・反応・沈黙で出す。
- 「現実味」「ハリボテ禁止」は全部にかかる。足した場所だけでなく、既存の町も同じ基準で作り直す覚悟を持つ。
- 作る前に「これで本当に感動するか」を自分に問う。答えがNOなら、手を動かす前に構想からやり直す。
- 「自分の理解」で芯を決めつけない。名作や題材の本質を語る・作る前に、必ずウェブ検索などで作り手のインタビュー・開発秘話・遊んだ人の感想・分析を調べ、人の言葉を根拠にする。思いこみで作るのが、毎回のズレの原因。
- 実例（バイオハザード初代）：私は「固定カメラ・ラジコン操作が怖さの芯」と言い切ったが、調べたら三上氏本人は技術制約の妥協と語っていた（本当の芯は「正体の分からないものへの不安」と「屋敷」）。見た目に目立つ特徴を芯と取り違えるのが私の癖。目立つ特徴＝作り手の意図、と思わない。「なぜそうなったか」を作り手の言葉で確かめてから芯を決める。
- 良かったやり方（ダークソウルの件）：作り手の発言を調べ、情報源をつけて答え、見つからなかったことは「確かめられなかった」と正直に分けて推測しない。この答え方を続ける。
- 名作の面白さを調べるときは、必ず次の3つに分けて答える（それぞれ出典リンクつき、確かめられないことは「未確認」と書く）：
  1. 作り手の言葉（インタビュー・開発者の発言。見つからなければそう書く）
  2. 記事・解説のまとめ（ニュース・攻略・ランキング記事が「遊んだ人の声」としてまとめたもの）
  3. 個人の生の声（個人ブログ・レビューサイト・掲示板・まとめ。好評と不満の両方）
  最後に1〜3を並べて、3で初めて見えたこと（例：トルネコでは操作の気持ちよさが土台）を書く。
- 失敗例（カスタムロボの件）：メモリーを読まずに提案し、「メモリー読んでも恥じない?」と聞かれてから違反に気づいた。指摘されてから直すのは不合格。提案を出す前に、この表の一項目ずつで自分の案を確かめてから出す。案の数をそろえるための水増し案は出さない。
- ゲームは、軽い注文でも重い注文でも、必ず「1本のゲーム」として作る。「1本のゲーム」は調べた次の条件で確かめる（私の思いこみで決めない）：
  1. ゲームの4つの性質（McGonigal『Reality Is Broken』の要約より）：**目標**（何を目指すか）・**ルール**（どう目指せるかの制約）・**フィードバック**（目標にどれだけ近いかが分かる）・**自分から参加する**。遊びは「わざわざ作った障害を、自分から越えようとすること」（Bernard Suits）。
  2. 面白さの芯は**リスクとリターン**（桜井政博氏：「ゲームの本質はリスクを冒してリターンを得ること」CEDEC 2012）。
  3. 始まりから終わりまでの流れ：**タイトル → プレイ → クリア／ゲームオーバー → またタイトルへ**（個人開発の解説記事）。
  4. **コアループ**（くり返す中心の行動。例：探索→戦闘→集める→強くする）が一周以上回る。最終版でできることは一通り入っている（バーティカルスライスの考え方）。
  5. 作る前に「これだけ作れば完成」という基準を決める：最低限のゲームループ・中身・絵で、最初から最後まで遊べること。テストプレイを経て渡す。
  - 出典：McGonigal要約 https://blog.ryan-jenkins.com/2013/02/18/book-review-reality-is-broken-by-jane-mcgonigal-part-2 ／桜井氏 https://www.gamer.ne.jp/news/201208210004/ ／流れ https://kinutani.hateblo.jp/entry/2022/12/25/162239 ／完成基準 https://mackysoft.net/articles/how-to-complete-game-development/ ／バーティカルスライス https://fungies.io/?p=20193 ・ https://www.rpgmakerweb.com/blog/5-ways-to-rapid-prototype-your-game
  - 戦闘だけ・画面だけの見本で出さない。案を見せるときも、上の1〜5を満たす1本として見せる。
- 手抜きをしない。具体的には：
  - 見本・仮の絵・仮の文・「あとで直す」で済ませない。出す物は全部、遊ぶ人の目に触れる完成品として作る。
  - 置いた物・書いた仕組みは、全部ちゃんと動き、意味がある（調べれば一言返ってくる、鍵には理由がある）。
  - 最初から最後まで自分で通し（ボットの通しプレイ）、詰まない・落ちないことを確かめる。全部の部屋・全部のカメラを写真で一枚ずつ見て、おかしい所を直してから渡す。
  - 時間や量の都合で削るなら、削ったことを正直に書く。黙って削らない。
  - 「スマホで遊べる」と言うなら、画面の写真ではなく、スマホとして開いて指の操作（たたく・なぞる）だけで、タイトルから最後まで動かして確かめる。渡し方も、スマホで開けるリンクにする（黄泉還で、タイトルの項目が指で選べないまま「スマホでも遊べる」と渡した失敗から）。
